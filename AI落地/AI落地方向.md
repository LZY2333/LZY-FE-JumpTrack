# AI 工程化规范

## 一、能力提升策略

为了提升企业内网大模型的实际使用效果，可从以下方向进行优化：

### 1. 编写高质量 Prompt

明确 AI 的角色、任务背景、目标、限制条件和输出格式，必要时提供 Few-shot 示例，提升模型理解准确性。

### 2. 沉淀标准 Prompt 模板

针对代码生成、代码 Review、需求分析、SQL 编写、Bug 定位等高频场景，沉淀团队统一 Prompt 模板，降低使用成本，提高输出一致性。

### 3. 缩小问题范围

避免一次提出过于宽泛的问题，将复杂问题拆分为明确、具体的任务，减少模型发散和无效输出。

### 4. 拆解复杂任务

复杂需求不直接进入 Coding 阶段，应先进行任务分析和方案拆解，输出 Plan 后再执行开发。

### 5. 提供充分上下文

为 AI 提供必要的项目背景、代码结构、接口文档、数据库信息、日志等上下文，减少模型猜测，提高结果准确率。

### 6. 引导先分析再回答

要求 AI 先分析问题、说明思路，再输出解决方案，避免直接生成未经验证的结果。

### 7. 固定输出模板

统一 AI 输出格式，例如：

```
问题分析

解决方案

风险点

实施步骤

代码修改
```

提高输出质量和可读性。

## 二、落地实施方案

| 优化方向 | 落地方向 |
| --- | --- |
| 编写高质量 Prompt | 沉淀为 Skill，规范 AI 思考方式和任务处理流程 |
| 标准 Prompt 模板 | 建立 prompts 目录，沉淀团队常用 Prompt |
| 缩小问题范围 | 通过 Skill 指导 AI 明确问题边界 |
| 复杂任务拆解 | 建立 gen-plan Skill，要求复杂任务先生成执行计划 |
| 提供充分上下文 | 建设 AI 友好型项目文档，包括 README、AGENTS、database 等 |
| 先分析再回答 | 写入 AGENTS.md，作为 AI 工作流程规范 |
| 固定输出模板 | 沉淀到 Skill，统一 AI 输出结构 |

## 三、项目结构规范

AI 友好型项目建议采用以下结构：

```text
project/
│
├── README.md                 # 项目：介绍项目背景、启动方式、开发流程等
│
├── AGENTS.md                 # AI：定义 AI 工作规范、编码规范、协作方式等
│
├── database/                 # 数据：沉淀数据库模型、字段说明、建表结构等
│   ├── database.md           # 数据模型说明、表关系、字段含义、业务约束
│   └── ddl/                  # 原始数据库结构，如建表 SQL、索引 SQL
│
├── prompts/                  # 人：沉淀团队常用 Prompt 模板，降低 AI 使用门槛
│
└── skills/                   # AI能力：沉淀 AI 工作方法、任务处理流程和最佳实践
```

核心原则：

- README 负责介绍项目。
- AGENTS 负责约束 AI。
- database 负责提供数据上下文。
- prompts 负责提升团队使用效率。
- skills 负责沉淀 AI 能力。

## 四、文件职责说明

## README.md

定位：

> 项目入口文档，帮助开发者和 AI 快速了解项目。

主要内容：

- 项目简介
- 技术栈
- 目录结构
- 本地启动方式
- 开发环境
- 常用命令
- 调试方式
- 部署流程

---

## AGENTS.md

定位：

> AI 工作规范文档，定义 AI 在项目中的行为方式。

建议包含：

### 1. 项目简介

简要说明项目定位和业务目标。

### 2. 技术栈

说明项目使用的主要技术：

- 前端框架
- 后端框架
- 数据库
- 中间件
- 构建工具

### 3. 文档阅读顺序

AI 开始任务时：

```text
README.md
    ↓
AGENTS.md
    ↓
database/
    ↓
相关代码
    ↓
开始分析
```

### 4. AI 工作流程

复杂任务遵循：

```text
理解需求
    ↓
分析问题
    ↓
输出 Plan
    ↓
确认方案（可选）
    ↓
Coding
    ↓
Self Check
    ↓
输出结果
```

要求：

- 不直接开始 Coding。
- 复杂需求必须先输出 Plan。
- 不确定的信息需要明确说明。
- 优先进行最小范围修改。

### 5. 编码规范

包含：

- 命名规范
- 目录规范
- 注释规范
- 代码风格
- 错误处理规范
- 提交规范
- 项目已有设计约束

### 6. 回答规范

要求：

- 先分析，再回答。
- 说明修改原因。
- 提供风险说明。
- 保持项目现有代码风格。
- 输出结构清晰。

### 7. Skill 使用规范

根据任务类型选择对应 Skill：

- 需求分析 → requirement Skill
- 复杂任务 → gen-plan Skill
- 代码 Review → review Skill
- SQL 分析 → sql Skill
- Bug 定位 → bug Skill

## database/

定位：

> 提供 AI 理解数据库结构所需的信息。

目录：

```text
database/

├── database.md
└── ddl/
```

其中：

### database.md

负责说明：

- 数据库整体结构
- 表用途
- 表之间关系
- 字段含义
- 状态枚举
- 状态流转
- 特殊业务约束

### ddl/

负责保存：

- CREATE TABLE
- CREATE INDEX
- 字段定义
- 数据库真实结构

---

## prompts/

定位：

> 面向开发者的 Prompt 模板库。

用于沉淀：

- Bug 分析模板
- 功能开发模板
- SQL 编写模板
- Code Review 模板
- 需求分析模板
- 测试用例生成模板

目标：

让团队成员无需重复设计 Prompt，提高 AI 使用效率。

---

## skills/

定位：

> 沉淀 AI 的任务处理能力和最佳实践。

用于定义：

- 如何分析问题
- 如何拆解任务
- 如何生成 Plan
- 如何 Review 代码
- 如何定位 Bug
- 如何输出结果

目标：

将个人 AI 使用经验沉淀为团队共享能力。

---

## 总结

AI 友好型项目的核心不是增加大量文档，而是让 AI 能快速获得：

1. 项目背景（README）
2. 工作规范（AGENTS）
3. 数据上下文（database）
4. 使用方法（prompts）
5. 思考能力（skills）

通过工程化方式沉淀团队 AI 使用经验，提高开发效率和输出质量。
